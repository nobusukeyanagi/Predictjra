# Predictjra 単勝 D3.18（v88）

D3.17（v87）までの累積ロジックを維持し、通常D3への **reclaim（復帰）のタイミングだけを再調整**した累積版です。新しい選択方式や入力特徴は追加していません。

## v88 / D3.18 で追加した点

1. **Early power-only reclaim を厳格化**
   - `currentPower` 差だけで通常D3へ戻す早期条件を **15pt → 17pt** に変更
   - Power単独の一時的な差でEV候補を早く捨てすぎるのを抑制
2. **Late power+Recent reclaim を少し拡張**
   - EV sprint / momentum 判定後の復帰条件を **Power 12pt → 11pt** に変更
   - ただし `Recent +6pt` の裏付けは引き続き必須
3. **狙い**
   - 通常D3へ戻す判断そのものを増減させるより、**Recentの確認後に後段で戻す**比重を高める

## v71で追加した点

1. **価値差ゲート**
   - まず能力勝率・3着内率が安定している馬を「アンカー」にする
   - 割安馬へ本命を変更するのは、`edge` と `D3 EV` が最低値を超え、さらにアンカーより一定割合以上強い時だけ
   - 想定人気5位以下へ変更する場合は、人気が下がるほど必要な優位差を少し大きくする
2. **全レース購入向けの守り**
   - 毎レース100円を必ず買うため、「価値馬が弱いのに無理に穴へ行く」挙動を抑制
   - 価値差が小さいレースでは能力勝率の高い馬へ戻す
3. **80%フロア最適化**
   - optimizer の標準目標を100%から80%へ変更
   - 全体だけでなく月別下位25%と、時系列5分割の下位25%も評価
   - 80%からの不足幅を明示的に罰する
4. **探索数を増やしすぎない**
   - 新しいゲート条件を追加する一方、既存グリッドを整理し、約4,608条件に抑制

### Run-consensus guard

- 価値候補の `_total` が信頼度アンカーより **1ポイント以上低い**
- かつ `current_run` がアンカーより **11ポイント以上低い**

- 候補自身がアンカーの場合は影響しない

市場価値だけで本命を変更するには、少なくとも総合能力か今回走力のどちらかで十分な裏付けを求める考え方です。

## v86 / D3.16: policy reliability reclaim

v85のdual-EV合意オーバーライド、v84のanti-chase、およびv73以降の全ガードを維持したまま、
**単勝レジームが通常D3の即時能力シグナルに明確に逆行した時だけ通常D3へ戻す最終安全網**を追加します。

### 追加条件

レジーム／v85オーバーライドが選んだ単勝馬と通常D3（`policy`）本命が異なる場合、次のどちらかを満たせば通常D3へ戻します。

1. 通常D3本命の `currentRun` が選択馬より **11ポイント以上高く**、かつ `recentIndex` も **4ポイント以上高い**
2. 通常D3本命の `currentPower` が選択馬より **15ポイント以上高い**

このreclaimは100円単勝の最終段だけに作用し、三連単軸は従来どおりv81固定D3.11のままです。
またreclaim後の実績はレジーム判定用の3アクション履歴へフィードバックしません。
